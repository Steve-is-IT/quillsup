What is in the LMS shell for "Teaching Digital Safety and Cybersecurity in K-12," how to import it, what was checked, and what could not be tested. Read the last section before you rely on it.

No student accounts, no student data collected, ever. The shell contains no student data.

1. What you get#

1. What you get
File or folder What it is
Hackles_College_Course_CC1.1.imscc A Common Cartridge 1.1 package: 17 modules (Start Here, Weeks 1 to 15, Question bank), page resources, discussion topics, assignments as web pages, 8 quizzes in QTI 1.2, and a 150-item question bank. Best first choice
Hackles_College_Course_CC1.3.imscc The same content with Common Cartridge 1.3 namespaces and resource types, for platforms that prefer 1.3
Hackles_College_Course_CC1.1_Canvas_assignments.imscc CC 1.1 plus Canvas-style assignment_settings.xml files, so assignments may import as real (unpublished) assignments with points. Experimental. Use it only if the plain package imports cleanly and you want to try it
copy_paste_html/ Plain HTML pages for any LMS: index.html, syllabus.html, assignments.html, field_placement.html, reading_list.html, and week01.html to week15.html. Each week page has the plan, assignments, discussion prompt, journal prompt and (where due) a 10-item self-check quiz with answers in <details> blocks
../question_bank/ The CSV and QTI 1.2 versions of the 150-item bank, a QTI import zip, and a readable Markdown copy
../build/ The Python scripts that generate everything, including validate_cartridge.py

2. What is inside each week module#

  1. Week overview and plan (a page): outcomes, required and optional reading, the minute-by-minute agenda, Concepts Lab and Facilitator Kit methods, what is due, field tie-in, discussion and journal prompts. Instructor notes are not included in the student pages; they live in the Instructor Notes and Weekly Course Plans documents.
  2. Discussion topic: the week's prompt, with a reminder to reply to two peers with a glow and a question and to keep names and incident details out.
  3. Assignments due that week: journal entry (Weeks 1 to 13), surveys, observation and supervised lesson logs, micro-teach, practicum, unit plan milestones, capstone pieces, field log.
  4. Quiz in the weeks where one is due (Weeks 2, 4, 5, 6, 7, 9, 11 and 14).

The Start Here module holds the syllabus, Assignments and Rubrics, the Field Placement Guide and the Reading List. The last module holds the question bank for instructor use.

3. How to import#

Canvas. Course Settings, Import Course Content, content type "Common Cartridge 1.x Package," choose the .imscc file, import all content. For the question bank alone, choose "QTI .zip file" and use question_bank/Hackles_College_Question_Bank_QTI12.zip.

Other platforms. Moodle, Blackboard, D2L Brightspace and Sakai all advertise Common Cartridge import. Use the CC 1.1 file first, then CC 1.3. If anything fails, use the copy-paste HTML pages: open each file, copy everything inside <main>, and paste into the LMS page editor in HTML view. [None of these platforms was tested; see Section 6.]

4. What you must set by hand after import#

A Common Cartridge does not carry everything. After importing, set the following in your LMS.

4. What you must set by hand after import
Setting What to do
Dates Cartridge files carry no term dates. Set due dates from the week numbers
Points and weights Create assignment groups with these weights: Quizzes and surveys 10%, Reflective journal 10% (drop the lowest one score), Micro-teach 15%, Disclosure practicum 15%, Unit plan 20%, Capstone 20%, Field and dispositions 10%
Assignments In the plain package, assignments are pages titled "Assignment (create in your LMS)". Create an assignment for each, using the page text as its description, and set submission types (online text or file upload)
Quizzes Check each imported quiz: 10 questions, two attempts, best score kept, mastery at 8 of 10. Turn off any feature that reveals answers before the deadline if you reuse items
Question bank Check that the bank imported as a question bank, or import the QTI zip separately
Accessibility Run your LMS accessibility checker on every page. Add captions to any video you add. The pages use real headings, lists, table header cells and a skip link; the Canvas editor may rewrite some markup
Privacy and access Publish only to enrolled candidates. Turn off public access. Do not enable features that collect student data from K-12 learners; this shell is for college candidates only
Names Replace [INSTITUTION], [INSTRUCTOR], [COUNSELOR PARTNER] and campus office placeholders in the syllabus page

5. Design notes#

  • Structure. One top-level module per week so that Canvas and most platforms create a module from each organization item.
  • Voice and safety. Every page begins with the license notice. High-care weeks (8 and 9) carry a content note and the choice to take any role or the written alternative.
  • Quiz items. Each quiz draws 10 of the module's items from the bank by a fixed seed. The answer, rationale and kit source appear in the feedback field. No item has been field-tested.
  • Accessible by design, not by audit. Palette is the Field Guide set (ink #2B2D42 on paper #FAF4E4, a contrast of 12.29 to 1 per the kit's design system). No images are used, so there are no alt-text gaps. Tables have header rows.

6. What was checked and what could not be tested (read this)#

Checked, by script (build/validate_cartridge.py).

  • Each .imscc file is a valid zip with imsmanifest.xml at the root.
  • Every XML file is well formed.
  • Namespaces and schemaversion match the cartridge version.
  • All identifiers are unique. Every identifierref points to a resource. Every file href exists in the zip. Every resource is placed in a module. No unlisted files other than the shared stylesheet.
  • All resource types fall within the set expected for Common Cartridge 1.1 or 1.3.
  • Every QTI item has four choices and an answer key that matches one of them. The CC packages contain 230 QTI items (8 quizzes of 10 plus the 150-item bank); the stand-alone question bank contains 150.
  • The HTML pages build without unreplaced placeholders.

Not tested.

  • No real LMS import was performed. Canvas, Moodle, Blackboard, Brightspace and Sakai were not available in this build environment. The packages follow the structure of Common Cartridge as best recalled and are structurally consistent, but a platform may reject or partly import them. Expect to fix small things.
  • No validation against the official IMS XSD schemas. The schema files were not downloaded and checked. The CC 1.3 namespaces, schema locations and resource-type strings were written from memory of the specification and are the most likely place for a platform to complain.
  • The Canvas-style assignment files are an experiment. The assignment_settings.xml layout follows what Canvas exports as best recalled. If the Canvas variant fails, use the plain CC 1.1 package.
  • QTI rendering and feedback. QTI 1.2 items include per-item feedback, but how each LMS displays feedback, applies attempts and handles question banks was not tested. Some platforms ignore cc_maxattempts; check attempts and set them by hand.
  • Quiz import into a question bank (versus as a quiz) varies by platform.
  • Accessibility of the imported result was not audited with an LMS checker or a screen reader. Run your own.
  • Dates, weights, groups, rubrics and module prerequisites are not carried and are set by hand.
  • Slide decks are separate PowerPoint files (in ../slides/) and are not linked inside the cartridge.

If it does not import. Use the copy-paste HTML and the CSV bank. Both work in any LMS that accepts pasted HTML and CSV or QTI imports.

7. Keeping it current#

Re-verify the [VERIFY] items each term (see Instructor Notes, Section 10). To regenerate everything after you edit the course data: python build/build_docs.py, python build/build_qbank.py, python build/build_slides.py, python build/build_lms.py, then python build/validate_cartridge.py. Python 3 with python-pptx and lxml is needed; the other scripts use the standard library only.
